# 在 VLM 中拼接 token 时，只要训练和推理对齐，内部顺序影响通常不大

## Evidence
- 这条判断主要适用于把多模态输入统一送进 Transformer 的常见 VLM。对模型来说，token 顺序本质上是一种被位置编码和 special token 定义出来的序列化约定，而不是先验真理。
- 只要训练时和推理时使用同一套拼接方式，模型就能把“哪一段 token 来自图像、哪一段来自文本、边界在哪里”一起学进去。它适配的是整套输入格式，而不是某个唯一正确的内部顺序。
- 许多 VLM 实现都用过不同排布：图像在前、文本在前、插入模态占位符、或者把视觉 token 放在 instruction 附近。只要训练和推理遵守同一格式，内部顺序往往只是二阶因素。
- 真正更敏感的是分布错位。如果训练时主要看到 `[IMG][TEXT]`，推理时却改成 `[TEXT][IMG]`，或者连 special token 和边界定义也一起改了，位置先验和注意力路径都会漂移，退化通常比“先后顺序本身”更明显。
- 所以更关键的设计原则不是追求某个绝对最优顺序，而是先定好一种序列化约定，再让训练数据、模板、推理拼接和后处理全链路保持一致。
