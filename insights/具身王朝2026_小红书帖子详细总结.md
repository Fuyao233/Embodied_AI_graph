# 《具身王朝2026》详细总结

> 来源：用户提供的小红书帖子（标题：`具身王朝2026`）。
>
> 整理方式：读取公开页面正文，并对 39 张配图使用本机 `codex-ocr` 识别后归纳。文中公司、项目名和数字均按帖子内容转写；这是一份对帖子观点的整理，不是对论文或公司公告的独立事实核验。

## 一、帖子在讨论什么

文章用“明代御前议事、户部报账”的戏剧形式，盘点 2026 年具身智能领域的主要路线。表面上是在争论 VLA、WAM、JEPA、World Model 谁代表下一代，实际主线是：

> 不能只报数据量、参数量和成功率，还要说明这些资源为什么在某家公司或研究团队手里真正转化成了能力。

作者把行业的“账”拆成几类：数据从哪里来、数据如何混合和标注、训练 recipe 怎么设计、模型能否跨机器人和跨环境迁移、部署后的经验能否回流、失败轨迹能否复用，以及系统中有多少能力其实来自人为写好的接口和工程闭环。

## 二、数据规模与数据价值

### 1. “一百万小时”和“十二秒”不是同一笔账

- **Dyna-2**：帖子提到约一百万小时的第一视角人类视频，把视频视为新的 scaling axis。
- **GEN-1.5**：在 Dyna-2 之后，帖子提到一种新任务只需看一次、约 3 到 12 秒、不更新参数即可当场完成。
- 作者认为，前者主要是在讲 **pretraining/scaling**，后者是在讲 **adaptation/one-shot generalization**。两者都重要，但不能用“十二秒”去替代“一百万小时”，也不能把二者放到同一栏宣传。

帖子批评行业常见的叙述方式：数据量大的项目强调 scaling，少量新任务数据的项目强调 data efficiency，换环境仍需 post-training 的项目则把适配成本放到脚注里。作者的要求是把收益和代价同时报出来。

### 2. 数据源正在多元化

机器人自身采集的数据不够，因此各家公司在把不同来源的经验搬到机器人上：

- 人类第一视角视频和人类示范；
- 机器人 fleet 的真实部署轨迹；
- 其他机器人的控制数据；
- autonomous rollout，包括成功和失败轨迹；
- 仿真、世界模型和合成数据；
- 直接从人手上采集动作的手套或技能捕捉数据。

作者并不反对继续开数据源，反对的是把“数据更多”当成解释一切的答案。

### 3. 混合数据必须有语义标签

帖子以 **πo.7** 为例，强调混合数据包括不同机器人、control modality、人类视频、autonomous rollout、成功/失败、快/慢、左右侧等。若直接把这些数据拼在一起，模型不一定知道它们为什么不同，甚至可能让相互冲突的 strategy 彼此干扰。

建议至少补充以下信息：

- strategy：采用了哪种策略；
- quality：轨迹质量；
- speed：执行速度；
- control modality：控制模态；
- visual subgoal：当前视觉子目标；
- failure reason：失败方式与失败原因。

同一条 failure，如果没有上下文，可能是“毒药”；如果明确说明怎么失败、为什么失败、属于哪种策略，就可能变成有价值的监督信号。

## 三、训练方法：差距不只在模型和数据

### 1. RoboTTT/GR00T：长上下文与 test-time training

帖子提到 **RoboTTT** 的底层仍是 **GR00T N1.7**，重点不是更换 base model，而是把历史拉长到约 **8000 timestep、约五分钟**。机器人不再只看几步或几十步，而是处理更长的视觉、本体状态和动作历史。

相关训练 recipe 包括：

- test-time training；
- sequence action forcing；
- 截断 backpropagation through time；
- 区分只用于更新 fast weights 的 timestep 与真正计算 action loss 的 timestep；
- 人类 demonstration 的前段作为 context，不强制模型模仿前段 action；
- DAgger distillation 中，把机器人之前的错误作为 context，把人的 correction 作为 target。

作者借此强调：同一条 correction，单独给出只是答案；把“模型如何错的”也放进去，才提供了为什么要改的因果背景。

### 2. 迭代计算可能比“多模态”更关键

帖子引用 ICLR 论文 **Much Ado About Noising**，质疑 diffusion policy/flow policy 常被归因于 multimodal action distribution 的说法。文中称，在一些 benchmark 上，真正贡献可能主要来自 **iterative computation、intermediate supervision 和 stochasticity**，简单的两步 regression policy 也能接近其表现。

作者没有据此宣布 generative policy 无效，而是提醒：模型有效与研究者真正知道它为何有效，是两回事。

## 四、World Model、WAM 与 JEPA：同名路线并不相同

### 1. “WAM”不是单一技术

帖子提到 **NVIDIA Beyond VLAs**、**DreamZero**、**Cosmos**、**Dyna-2**、**Hydra-0** 等项目，但明确指出它们的 world model 用法不同：

- DreamZero：把 future video 与 action 联合学习；
- Cosmos：尝试把 reasoning、world generation、action generation 放在一起；
- Dyna-2：训练时预测 future video，但 policy inference 时未必需要先生成那段未来视频；
- 有的 world prediction 用于部署时规划；
- 有的把 world model 当训练目标；
- 有的用于 synthetic data；
- 有的用于 evaluator。

因此，“机器人先想象未来再行动”已经不足以概括所有 WAM。名字相同，不代表训练目标、部署位置和评估方式相同。

### 2. JEPA/AMI Labs 关注“到底学到了什么”

帖子提到 LeCun 离开 Meta 后创办 **AMI Labs**，继续押注 world model，并列出几条 JEPA 方向：

- **V-JEPA 2.1**：更密、更稳定的时序表征；
- **LeWorldModel**：追问 JEPA 是否必须依赖复杂稳定器，能否更直接地从 pixel 端到端训练；
- **SkyJEPA**：往更高频、更长时域的飞行控制推进；
- **AdaJEPA**：world model 训练完成后，面对真实 dynamics 变化，能否通过新 transition 持续适应；
- JEPA-WAM 相关工作：一类在 V-JEPA latent space 中做 transition，另一类认为只预测短期物理变化不够，还应预测下一阶段的 semantic future。

作者真正关心的不是“JEPA 是否取代 WAM”，而是：latent 是否对应世界真实自由度，能否用于 planning 和控制，控制频率提高后是否仍然有效，现实动力学改变后能否跟着变化。

## 五、跨机器人本体泛化

### 1. XEWorld 暴露的问题

帖子提到 **XEWorld** 将训练中见过的机器人移除，换成新的 embodiment，测试模型学到的是 dynamics，还是只记住了机器人外观。文中称，不少模型更依赖视觉相似，而没有按 **kinematic similarity** 泛化；换一具身体后，数字 joint action 的意义也随之变化。

### 2. 两种不同解决思路

- **Hydra-0**：不在 joint space 中强行统一动作，而是把 action 表达成 pixel-space motion/pixel flow，以降低跨本体对齐难度。作者同时追问：这究竟是学到了共享动作结构，还是绕过了最难的 embodiment-specific dynamics？
- **Demo-JEPA**：不要求 source 与 target 的 action 对齐，先从 demonstration 学“世界应该变成什么样”，再让目标机器人根据自己的身体完成动作。

帖子结论是，跨 embodiment 这笔账才刚开始算，不能仅凭统一 action 表示或漂亮的迁移结果宣布问题解决。

## 六、从触觉、仿真到合成数据

### 1. 触觉和力觉进入主模型

作者认为，擦、插、压、拧等操作不能只靠画面判断：插头是否咬合、瓶盖是否卡住、夹持是否打滑、力是否过大，往往需要触觉和本体感觉。

- **Figure Helix 02**：把 touch 和 proprioception 接入 whole-body policy；
- **NVIDIA humanoid reference design**：配备 tactile hand；
- **ForceVLA2**：把 force awareness 与 hybrid force-position control 纳入 VLA；
- **TouchWorld**：将 tactile 单独建成 predictive/reactive model，高层预测接触结果，低层用高频触觉反馈修正。

### 2. NVIDIA 的仿真与世界生成工具链

帖子列出 **Cosmos、Isaac、MimicGen**，认为它们的目标是把昂贵的真实轨迹放大成更多训练经验。但合成数据不能只报生成数量，还必须回答：

- 生成了什么；
- distribution 如何设计；
- variation 是否合理；
- 接触是否符合现实；
- 失败模式是否真实存在。

如果 world model 本身错了，生成一百万条数据只是在把错误复制一百万遍。

## 七、适配成本、长任务与强化学习

### 1. Sunday：从人的技能到机器人适配

- **Sunday** 不先收 robot data，而是通过 **Skill Capture Glove** 从人手上采集，再转移到机器人。
- 帖子还强调 Sunday 关注“pretraining 足够强后，一条 post-training demonstration 能否迁移到别的环境”。
- 作者赞成把 adaptation cost 单独核算：如果每换一个厨房、衣服或客户都要重新采数据和 fine-tune，就不能只宣传 generalist。

### 2. Figure：whole-body 与 fleet 闭环

- **Figure Helix 02** 仍被归为 VLA，但方向是把 upper-body policy 推向 whole-body；视觉、触觉、本体感觉覆盖手臂、躯干和腿，并按不同时间尺度运行。
- Figure 更重要的资产是 **fleet**：制造、部署和学习不是三件分开的事。机器人部署后，轨迹如何回流、如何筛选、如何重新训练、下一代是否真的少犯前一代的错，决定 fleet 是否形成数据闭环。
- 作者提醒：部署一万小时不等于得到一万小时可用资产，可能只有一万小时录像。

### 3. RoboTTT、Physical Intelligence MEM 与 To-VLA：处理长任务

- **RoboTTT**：把长历史写入 fast weights；
- **Physical Intelligence MEM**：短期视觉记忆 + 长期语言记忆；
- **To-VLA**：从决策端分配计算，简单子任务直接执行，困难子任务生成多个候选，再用 world model 比较和选择。

长任务的难点已从“这一步会不会做”变成：刚才做过什么、还剩什么、物品放在哪里、任务被打断后从哪一步恢复。

### 4. RL Token：把“看会”变成“练熟”

帖子提到 **RL Token**：不把整个大 VLA 拿去在线强化学习，而是抽取紧凑表示，让小型 actor-critic 使用真实 interaction 继续训练。核心观点是：预训练模型会插头、拧螺丝，不等于执行得又快又稳；看别人做一百遍，与自己练坏十块板，不是同一回事。

## 八、抽象、Coding Agent 与自动化研究

### 1. CaP-X：模型能力还是人写的脚手架

**CaP-X** 被用来讨论高级 API/abstraction 的贡献。给 coding agent 一个 `grasp()`，它能完成抓取；把接口拆成更低级 primitive，性能就下降。作者认为，论文报告 agent 会多少任务时，也应说明 API 已经替它完成了哪一层工作。

CaP-X 后续思路是撤掉部分 abstraction，增加 interaction、execution feedback 和 visual differencing，再让 agent 自己进行 skill synthesis。

### 2. ASPIRE 与 ENPIRE：失败驱动的技能和研究闭环

- **ASPIRE**：读取失败 trace、定位错误、修改代码、重新验证，验证通过后存进 skill library。
- **ENPIRE**：让 coding agent 自己查资料、改方案、跑 fleet、自动 verify，遇到 failure 后继续修改。

作者指出，实验室一年能试一百个 idea 还是十个，不只取决于模型大小，还取决于 reset 是否自动、verifier 是否可靠、真机能否并行、failure trace 是否完整、修改后能否自动跑 regression test。

## 十、文章的最终判断

文章没有选择“VLA 已死”或“WAM 已统一”的结论，而是认为各条路线仍在并行演化：

- 数据采集继续扩大；
- WAM 和 JEPA 继续研究；
- VLA 继续加入记忆、whole-body、RL、world model、触觉和长上下文；
- Figure 继续造机器人，NVIDIA 继续造世界与仿真工具，Sunday 继续从人身上采集技能，π 继续利用 failure，RoboTTT 继续拉长 context。

真正值得下一年度“报账”的，不是又换了什么名字，而是以下可验证增量：

1. 一种以前没有的数据用法；
2. 一种新的训练办法；
3. 一种更可迁移的 action representation；
4. 一种降低 adaptation cost 的方法；
5. 一种让 failure 留下来并可复用的机制；
6. 一条把部署、验证、修正和再训练接起来的闭环。

如果删掉名字、参数量和训练小时后什么也不剩，剩下的就只是规模。规模有价值，但不能把规模写成能力本身。

## 十一、适合快速转述的摘要

这篇文章借“御前报账”讽刺具身智能行业的指标竞赛：大家都在报百万小时数据、超长 context、新模型和新路线，但真正难复制的部分往往藏在数据筛选、训练顺序、失败处理、人工抽象、部署闭环和工程系统里。VLA、WAM、JEPA 并非简单的朝代更替，而是不同组件逐渐叠加。判断一家公司是否真正领先，应看它能否把数据转化为跨任务、跨本体、跨环境、可持续改进的实际能力，并明确报告适配和部署成本。
